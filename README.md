# 再消一行

面向TapTap H5的Three.js方块游戏。GM只维护Three一个引擎；本项目负责玩法与视觉，自有框架提供运行时、控件、输入、资源、音频及测试/性能协议。

## 从哪里开始

- [代码导航](代码/README.md)：应用、规则、视觉、配置接入与开发协议。
- [配置导航](配置/README.md)：项目设置、玩法运行值与渠道发布配置。
- [组件](组件/README.md)：项目独立维护的视觉配方和真实预览登记。
- [功能策划](文档/功能策划/README.md)：版本化需求；历史稿件保留，当前源码位置以代码导航为准。
- [TapTap项目手册](文档/TapTap项目手册.md)：渠道接入与上线约束。

## 运行和检查

```sh
bun run dev
bun run typecheck
bun test
bun run build
bun run build:验收
```

`index.html`是唯一游戏宿主，加载`代码/应用/启动.ts`。运行脚本在`运行/`；`build`调用GM正式打包，产物只有`产物/`，包含同一构建的模块字节与源码指纹记录。`build:验收`只把测试图片和资源验收页写入`.gamemaker/资源验收/`。打包报告写`reports/打包/打包报告.md`，不作为策划或源码提交。

`框架/`、`游戏模块库/`、`GM工具/`均为本机目录联接，不提交Git。前两者提供框架与配置协议，GM工具只供运行脚本调用，不进入游戏运行图。依赖安装在各自项目合理，构建必须复用GM的单引擎解析，不能把两份Three内联。

GM看板经组件登记、标准测试桥和性能桥对接开发游戏。资源草稿、测试桥、性能观测与看板目录不进入外部包。测试桥和样本统一在`测试/接入/`；`bun run build --验收` 生成`.gamemaker/测试包/`，保留内部功能/性能测试。普通`build`输出唯一`产物/`，用于外部测试或发布。旧产物已移入`.gamemaker/历史产物/`。

发布配置仍由`配置/TapTap发布.json`唯一维护，构建只注入公开平台运行字段；录制、发布和本地键配置留在工具端。项目主题保存完整配方并显式登记，不携带框架默认主题。最终ZIP在`/game/`子路径回放真实点击、逐步核对画面，内部参考包只提供控件位置与状态断言，不向外部包注入桥。

默认验收手机390×844、DPR1，以`配置/项目设置.json`为准。浏览器模拟不是手机真机；报告保存在`reports/`。改完须检查当前源码构建及真实页面，旧包截图不能证明新源码通过。
