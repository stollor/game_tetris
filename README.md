# 再消一行

## 运行和检查

```sh
bun run dev
bun run typecheck
bun test
bun run build
bun run build:验收
```

`index.html`是唯一游戏宿主，加载`代码/应用/启动.ts`。运行脚本在`运行/`；`build`调用GM正式打包，产物在`产物/<渠道>/`（默认外部包在`产物/外部/`，含`源文件/`与ZIP），包含同一构建的模块字节与源码指纹记录。`build:验收`只把测试图片和资源验收页写入`.gamemaker/资源验收/`。打包报告写`reports/打包/打包报告.md`，不作为策划或源码提交。

`框架/`、`游戏模块库/`、`GM工具/`均为本机目录联接，不提交Git。前两者提供框架与配置协议，GM工具只供运行脚本调用，不进入游戏运行图。依赖安装在各自项目合理，构建必须复用GM的单引擎解析，不能把两份Three内联。

GM看板经预制体登记、标准测试桥和性能桥对接开发游戏。资源草稿、测试桥、性能观测与看板目录不进入外部包。测试桥和样本统一在`测试/接入/`；`bun run build --验收` 生成`.gamemaker/测试包/`，保留内部功能/性能测试。普通`build`输出`产物/外部/`，用于外部测试或发布。旧产物已移入`.gamemaker/历史产物/`。

发布配置仍由`配置/TapTap发布.json`唯一维护，构建只注入公开平台运行字段；录制、发布和本地键配置留在工具端。项目主题保存完整配方并显式登记，不携带框架默认主题。最终ZIP在`/game/`子路径回放真实点击、逐步核对画面，内部参考包只提供控件位置与状态断言，不向外部包注入桥。

默认验收手机390×844、DPR1，以`配置/项目设置.json`为准。浏览器模拟不是手机真机；报告保存在`reports/`。改完须检查当前源码构建及真实页面，旧包截图不能证明新源码通过。

界面验收：项目根运行 `bun 测试/浏览器/虚拟列表与纯享.ts http://127.0.0.1:3000`（先在GM运行 `bun run gm -- 运行游戏 再消一行`），仅使用手机390×844、DPR1的Chrome模拟视口；截图与回执写 `reports/虚拟列表与纯享/`。双向过渡、中英文可读性与全部成就图标使用 `bun 测试/浏览器/双向过渡与可读性.ts <实际游戏地址>`，结果写 `reports/双向过渡与可读性/`。

收藏居中与自适应列表：`bun 测试/浏览器/自适应列表.ts <实际游戏地址>`，检查390×844下卡片左右等距、滚动完整和返回/英文画面，证据写 `reports/自适应列表/`。成就、商店与设置共用框架 `列表`，按实际子控件工作量、可视范围和CPU耗时选择普通/虚拟模式；页面自绘只遍历可视项。

结算演出：`bun 测试/浏览器/结算演出.ts <实际游戏地址>`，手机390×844 DPR1，使用真实45秒有效对局及15次落块验证奖励、提示上移消失、分数与金币常驻、按钮按压取消/重开和英文省电；结果写 `reports/结算循环/`。新纪录爆发入场后接轻循环，提示结束后轮播本局收藏，正常档按30Hz请求绘制、省电档按100ms心跳推进；循环不触发发奖。保存失败保留独立重试操作。看板「方块结算」可播放和定格同源配方的入场、收益与待机阶段。

文字与操作盘：`bun 测试/浏览器/文字与操作盘.ts <实际游戏地址>`，仅用手机390×844 Chromium模拟视口（DPR1/DPR2独立context，非真机），采集首页、设置（含滚动下半与语言下拉）、成就、商店、模式选择、马拉松、暂停、对局设置与结算，并校验真实双击软降无消行0分/无流光、单行消除最终1100；截图和JSON写 `reports/文字与操作盘/`，清晰度需人工查看截图。
