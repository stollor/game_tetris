# 再消一行

面向 TapTap H5 的单机网页方块游戏，使用 Bun、TypeScript 与 **Three.js**。现行游戏、开发、测试和正式打包都只走 Three。

游戏包含马拉松、冲刺、极限和每日挑战；支持暂停、结算、成就、排行榜降级、商店、主题与程序音频。玩法与项目专属视觉配方放在本仓库，Three 通用运行能力由 GameMaker 提供。

## 运行与检查

```sh
bun run dev
bun run build
bun run build:验收 # 单独构建测试图集/散图验收页，不作为正式发布包
bun run check
bun run typecheck
bun test
bun run test:browser -- http://127.0.0.1:3000
```

正式包由 GM CLI 构建：`bun run gm -- 打包游戏 再消一行`，发布入口为 `产物/index.html`。打包后先在目标环境打开并完成实际对局验收，再上传。

## Three 入口

- `index.html`：本地开发入口。
- `index.three.html`：GM 发布构建入口。
- `代码/three版/`：游戏页面、玩法接入、绘制、服务、音频和启动装配。
- `框架Three/`：指向 GM `游戏模块库/Three框架/` 的本机目录联接，不随游戏提交。
- `组件/`、`代码/视觉/`：游戏专属组件和视觉配方；运行时代码只由 Three 消费。

## 验收

- `测试/浏览器/three版验收.ts`：390×844 游戏流程和性能读数。
- `测试/浏览器/Three补完验收.ts`：设置、商店、滚动、结算、消行与结算动效交互。
- `测试/浏览器/文字DPI最小实验.ts`：文字栅格和像素对齐实验。

浏览器模拟视口不等同真机验收。目标平台和代表尺寸以 `配置/项目设置.json` 为准；性能结果及历史对照证据保存在 reports 中。

## 迁移后工具接入

标准测试桥由共享框架创建，节点来自页面实际登记，渲染序号只在成功提交后增加。测试控制继续使用框架的本机/局域网连接，命令注明存档影响；公网不连接GM控制服务。

启动先等待有单步8秒超时的云拉取，再创建设置/成就等本地服务；无能力或离线正常进入。结算本地纪录/成就/奖励成功后才自动尝试上传，平台失败不回滚本地。事件沿用已有分析缓冲，默认不向TapDB发请求。TapTap真机仍须正式发布前验收。

菜单/对局保存当前音乐场景，旅行装备和主题设置变化时统一重选。相同曲目不反复重启；暂停停止持续音乐/氛围并保留前台菜单操作音效；失焦和隐藏另挂起上下文，继续后按设置恢复；停止全部是最终销毁，取消订阅/监听并关闭AudioContext。

性能场景与方案在 测试/浏览器/性能场景.ts、性能方案.ts，三类方案均并发1。纹理压力走共享框架真实预算与GPU上传，结束释放。Three自身基线不能冒充旧版与新版同批交错的12项换轨对照。

资源验收用 测试/资源/ 下自己的小图与清单；开发路由 /测试资源/，build:验收 才复制进产物。默认build只有实际游戏与运行图集，不夹带测试图。GM根执行 bun 测试/浏览器/框架/迁移工具链.ts 可串行复跑真实控制、音频、宿主夹具、GM状态机和性能采样。

## 迁移生产链路

开发服务在入口刷新时复用GM配置指纹重建，失败返回500，修正后同端口刷新恢复；保留上一轮哈希资源，已打开对局不变。源码改动仍需正常重启。`游戏模块库/`与`框架Three/`均为本机联接，不提交。旅行音效装备通过既有地点音色转换进入实际移动、消行和连击，空或未知装备回退原谱。

发布ZIP验收登记于 `测试/浏览器/发布验收/状态机.json`，GM通过标准测试桥执行；不依赖私有调试桥。

运行参数以 `配置/配置表.json` 为准。当前马拉松目标100行与调慢后的速度表为用户确认的主动调参；`测试/配置与音频.test.ts` 固定这组已确认基线，界面目标回归见 `测试/three版模式与结算.test.ts`。调整参数后应同步审阅对应测试，不恢复旧140行规则来消除测试失败。
