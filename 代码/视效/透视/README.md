# 透视棋盘

立体晶格的项目专属 Three 表现。对局提交真实玩法快照，通过框架 `前置渲染` 在现有 2D 界面之前绘制，共用一个 WebGLRenderer。完整视觉参数只在[立体规范](../../主题/立体/立体规范.ts)声明。

## 空间与光照

- 正面镜头、10×20 正方格、棋盘投影和口沿占位保持一致。背墙高度占口沿视口的90%，顶底各留5%。
- 五个真实内表面组成敞口空腔。两侧壁板按行与进深分段，有厚度、倒角和小幅折面；缝隙露出暗色底墙。金属口沿前侧收窄，为现有占位中的墙面留出可见宽度。
- [房间装置](房间装置.ts)把金属、壁板、灯芯和灯芯柔光分别合批。八段侧灯和两盏顶灯使用真实 `RectAreaLight`，LTC查找纹理在模块首次使用时初始化并复用。
- 斜上方主光负责方块投影；环境与反射补光保留暗面的可读性。面光源产生附近墙壁受光和向棋盘内部衰减的蓝色照明。面光本身不投影，块间投影由主光提供。
- 方块使用按真实厚度构造的 `RoundedBoxGeometry` 与清漆物理材质，保留一致的倒角半径和真实法线。没有绘制出来的高光条、方块自发光或方块光晕面。
- 幽灵描边、锁定提亮与消行收缩消费同一份玩法状态。HUD、暂存/预览、操作键和覆盖页继续使用现有2D组件。
- 切回平面或离开对局时释放实例、几何、材质与主光阴影贴图。面光查找纹理由Three统一复用，随预览WebGL上下文生命周期结束。

`取景.ts` 是不依赖Three的投影纯函数；开口宽度随视口比展开，背墙格宽不变。`setViewport` / `setScissor` 接收逻辑像素，由渲染器统一处理DPR。

## 验证

在游戏项目根运行：

```sh
bun test 测试/立体棋盘.test.ts 测试/透视取景.test.ts
bun 测试/浏览器/立体棋盘.ts http://127.0.0.1:3000
```

规则检查真实几何厚度、倒角法线、壁板和面光源。浏览器使用真实Chrome、390×844、DPR1，通过正式操作搭建固定七色局面，锁定已确认的口沿/棋盘投影，采集格线、灯芯与同色方块不同面的亮度。随后真实点击移动、旋转、暂存、暂停及设置，验证单行消除、平面/立体切换和退出释放。

截图、绘制采样与交互结果保存在 `reports/立体棋盘/`。本次空间调校的开关灯对照与原始像素增量在 `reports/立体空间/`。手机视口模拟与短时绘制采样不能代表真机或完整性能闸门；视觉完成还需实际截图对照效果图。
