# 开发规范

## 技术栈

- Runtime 和包管理：Bun
- 语言：TypeScript
- 格式化和 Lint：Biome
- 单元测试：Bun 内置测试运行器
- 浏览器自动化：Playwright；GameMaker 的 `browser test` 使用项目内的状态流程

使用 Bun 管理依赖，不引入 npm、pnpm、yarn、ESLint、Prettier 或 Jest。

## 目录与命名

- 游戏业务目录、文件、类型和函数使用中文；生态配置名和标准 Web API 保持英文。
- 避免中英混合命名，如 `create方块`、`Game配置`。
- 文件职责以[代码导航](../代码/README.md)与[配置导航](../配置/README.md)为准；唯一宿主index.html，应用组装在代码/应用，规则与框架中间层分离。
- TypeScript 使用清晰的数据结构和明确的函数参数、返回值；不使用 `any`，也不用 `as unknown as` 逃避类型问题。
- 目录按实际职责命名，不建 `utils`/`helpers`/`common` 抽屉，不为未来可能的需求预建抽象层。

## 测试目录

- Bun 规则与纯函数测试：`测试/*.test.ts`，用 `bun test`。
- 实机脚本（点击、视口、截图、发声采样）：`测试/浏览器/*验收.ts`、`测试/浏览器/视觉快照.ts`，用 Playwright 跑真实页面，不使用 `*.test.ts` 后缀。
- 视觉与状态机产物目录（`测试/视觉审查/`、`测试/视觉快照/`、`测试/*功能流程/` 等）不提交，见 `.gitignore`。

## 修改后检查

```sh
bun run check
bun run typecheck
bun test
bun run build
```

音频接入与暂停行为见 `文档/音频接入.md`。
