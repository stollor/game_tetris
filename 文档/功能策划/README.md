# 俄罗斯方块现行功能策划

这里是 GameMaker 看板识别的结构化策划目录。入口与功能关系由 GM 管理：`项目.json` 只登记项目分组、功能文件和关系；每项功能独立一个 JSON，在看板“策划”页阅读。

## 迁移说明

现行策划依据项目原 `策划案/00-08`、当前源代码和测试入口补录。原始分阶段能力测试稿仍保留在 `策划案/`，用于追溯最初目标和阶段边界；不能把旧稿的 MVP 排除项当成当前版本限制。

| 分组 | GM 功能 | 原策划与现行依据 |
| --- | --- | --- |
| 共用玩法 | 共用棋盘与方块规则、键盘与触屏操作 | `策划案/02`、`策划案/07`、当前输入与规则实现 |
| 游戏模式 | 马拉松、冲刺、极限、每日挑战 | `策划案/03-06`、运行配置与本地纪录实现 |
| 界面与设置 | 菜单、设置与屏幕适配 | `策划案/07`、场景/设置/语言实现 |
| 视觉与音频 | 霓虹视觉与对局反馈、背景音乐与对局音效 | `策划案/07`、UI 配方、框架音频接入与实机验收 |
| 成就与纪录 | 成就与本地纪录 | 当前成就/存档实现及规则测试 |

这些稿件以 `补录: true` 标记，是按现行项目回填的正式策划基线，不伪装为过去存在的历史版本。`状态: 已实现` 表示代码有对应能力，不表示本次迁移重新验收通过；`验收` 字段是需要执行的检查计划，实际结果仍以测试和 `reports/` 证据为准。

`策划案/00-策划包说明.md`、`01-最小MVP.md` 与 `08-能力测试任务单.md` 是策划包介绍、早期 MVP 阶段规格和 Agent 测试流程，不是现行游戏功能，因此保留为历史输入但不伪装成星图功能。`02-共用核心规则.md` 与 `03-06` 拆入上表对应功能；`07-视觉交互与音频方向.md` 按当前职责拆为菜单/设置、视觉反馈和音频功能。

运行参数仍以 `配置/配置表.json` 为唯一运行值来源。策划说明规则和参数含义，不维护第二份可编辑数值表。视觉/音频样品、实际使用的来源文件及验收脚本在各功能稿 `来源` 中登记。

## 维护方式

- 新功能先运行 `bun run gm -- 看板 需求模板 俄罗斯方块 --JSON`，然后用需求新建预览/保存。
- 修改已有功能用文档读取得到的校验码、基线阶段和基线版本，先修订预览，再修订保存；不直接编辑功能 JSON。
- 当前功能关系通过关系修改预览/保存维护。仅登记实际依赖，不按菜单顺序猜测关系。
- 新旧策划冲突时先明确指出差异并形成修订；不默默把旧内容改成当前行为。

完整字段与请求格式见 GameMaker `文档/看板/AI调用.md`。
