# Phaser 游戏框架

新建游戏时，GameMaker 会把框架模块复制到生成项目的 `core/`。游戏入口负责组装场景并调用 `创建游戏框架()`；框架创建 Phaser 实例并提供各场景共用的基础能力。

## 模块

- `游戏框架.ts`：创建 Phaser 游戏实例，应用初始语言、主题和样式。
- `页面切换.ts`：场景之间切换、打开覆盖场景和返回。
- `设置.ts`：默认偏好、本地保存与设置变化事件。
- `音频.ts`：绑定 Phaser Sound Manager，播放背景音乐和音效，并响应静音与音量偏好。
- `多语言.ts` 与 `语言/`：按单语言单文件维护文案，由场景按文案键读取。
- `样式.ts`：应用样式属性并提供主色、面板、文字与轨道等语义化界面颜色。
- `组件/Phaser界面/`：共享尺寸契约的 UI 控件、可嵌套水平/垂直/换行布局、按钮、滑块、分组和下拉菜单；主界面与设置界面通过布局组合控件，尺寸和交互区域一起更新。
- `组件/Phaser界面/预制体配置.ts`：跨游戏预制体的默认字体、按钮、暂停面板和触屏布局；单个游戏可在构造预制体时覆盖外观参数。
- `组件/Phaser界面/模式卡片.ts`、`数值面板.ts`、`方块单元预制体.ts`：可以按数据重复实例化的卡片/指标组件，以及一致的程序化方块单元样式。
- `宿主样式.css`：只设置浏览器宿主页面与 Phaser Canvas 的铺满布局，不包含游戏界面样式。
- `测试桥接.ts`：只在本地开发地址扫描 Phaser 场景并提供通用快照；生成项目中复制到 `src/common/`。

## 功能测试接入

测试桥接自动读取当前可交互场景的 Phaser 对象。普通页面逻辑照常编写；测试希望优先定位某些对象时，只需在测试期间给 Phaser 对象设置 `name`。只要当前场景至少有一个命名交互对象，测试扫描就只提供这些对象；一个都没有时，则提供场景内全部交互对象。测试执行器通过 Canvas 坐标模拟真实鼠标操作，不调用页面回调。

```ts
按钮.name = "inventory.close";
按钮.setInteractive();
按钮.on("pointerup", () => this.关闭背包());
```

流程中的 `action` 可填写对象 `name`；无命名对象使用快照给出的自动 ID（`场景名/interactive-N`）。使用 `expectTextIncludes`、`expectTextChanged` 检查界面反馈，使用 `expectStorage` 检查持久化功能结果。滑块可填写数字 `value`，执行器会在实际命中区按比例拖动鼠标。

`示例/计数场景.ts` 和 `示例/计数功能流程.json` 展示了一个没有命名交互对象的普通 Phaser 页面如何被扫描并测试。示例不包含在新游戏默认文件中；需要时可复制到游戏项目并在入口场景列表中启用。

## 场景使用方式

```ts
import Phaser from "phaser";
import { 切换页面 } from "../../../core/页面切换";

export class 玩法页面 extends Phaser.Scene {
  constructor() {
    super("玩法页面");
  }

  create(): void {
    // 用 切换页面(this, "主界面") 返回菜单。
  }
}
```

当前依赖 Phaser `4.2.1`。模块之间允许存在清楚且必要的依赖；新增抽象前先确认它能解决多个游戏都会遇到的问题。

单个游戏的组合预制体与参数应留在游戏项目内；先真实使用，再把跨游戏稳定复用的部分沉淀到本框架。俄罗斯方块接入映射与外观调整入口见该游戏的 `src/预制体/README.md` 和 `src/配置/README.md`。
