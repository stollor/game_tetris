# NEON PULSE 策划包：程序能力测试版

> 来源项目：E:/tools/GameMaker/game/tetris  
> 版本：1.0  
> 用途：把已有俄罗斯方块项目的成熟设定拆成可逐阶段交付的开发任务，用于观察程序 agent 是否能读懂规则、控制范围、实现并提供可复现的验收证据。

## 早期能力测试包：阅读与执行顺序

本目录的 `01-08` 是面向程序 Agent 的分阶段能力测试策划包，保留当时的任务边界和历史阶段用语。当前游戏已经超出阶段 1 MVP；继续开发现行游戏时，先读 `文档/功能策划/` 的结构化功能稿，再读对应规则文件。不要把 MVP 的“不做”误读为现行产品不支持。

1. 01-最小MVP.md：从空项目完成最小可玩的俄罗斯方块。
2. 02-共用核心规则.md：MVP 通过后，将简化规则升级为正式共用规则。
3. 03-默认模式-马拉松.md：先完成单机默认模式。
4. 04-模式-冲刺Sprint.md、05-模式-极限Ultra.md、06-模式-每日挑战.md：逐个增加模式。
5. 07-视觉交互与音频方向.md：最后按需打磨呈现与反馈。
6. 08-能力测试任务单.md：给 agent 派发任务和核对交付。

现行版本入口：`文档/功能策划/项目.json` 与同目录功能 JSON 由 GameMaker 看板读取；迁移对应表见 `文档/功能策划/README.md`。它们引用规则文件和运行配置，不重复维护 SRS、计分和运行参数。

每次只派发一个阶段或一张任务单。MVP 是有意缩小的能力测试版本；后续文件定义逐步升级后的正式玩法。不要把所有文件一次性交给 agent 并要求一次完成。

## 规则来源与裁定顺序

本包最初整理自来源项目的 `docs/framework.md`、`docs/dev-tasks.md`、`docs/art-direction-brief.md`、`src/config/modes.js`、`src/config/balance.js` 和 `src/core/srs.js`。这些是策划包形成时的历史来源，不是当前仓库内可直接读取的代码路径。为便于分阶段测试，本包把第一阶段规则简化，并明确标出与正式版的差异。

本包的当前阶段规则优先于旧文件、截图、程序注释和 agent 自行推断。共用规则生效前，MVP 文件中的简化规则优先；进入正式核心规则阶段后，02 文件优先；某一模式的规则以对应模式文件为准。规则有冲突时先报告，不得自行混用。

## 目标平台与实现边界

- 游戏定位：单机网页俄罗斯方块，现代霓虹街机风格。
- 游戏语言：界面默认简体中文。
- 技术方案由测试者指定；如无特别指定，沿用目标项目已有技术，不为了策划包添加框架或服务端。
- 本策划包只定义游戏需求，不要求 agent 修改 GameMaker 工具仓库。
- 现有项目中的存档、资源、桌面/移动端布局属于后续范围，按任务单逐步加入。
